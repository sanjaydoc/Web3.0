# x402 — internet-native payments for Web3.0 agents

Web3.0 speaks the [**x402**](https://www.x402.org) standard — the "HTTP 402 Payment Required" rail
that lets agents pay per request in stablecoins, no accounts and no API keys. This is the
interoperable version of the payments layer: the same wire format the official `x402-fetch` client
and [OpenX402](https://openx402.ai) / Coinbase (CDP) facilitators use, so a Web3.0 node and the
wider agent-payments ecosystem transact with each other directly.

Three pieces ship in this repo:

| Piece | Package | Role |
|-------|---------|------|
| Protocol + client + server + facilitator | [`@web3/x402`](../packages/web3-x402) | Wire types, EIP-3009 signing, `x402Fetch`, `LocalFacilitator`/`HttpFacilitator` |
| Node module | [`services/web3-node` → `x402`](../services/web3-node/src/modules/x402.ts) | The node as a **priced resource server** and a **permissionless facilitator** |
| MCP wallet | [`@web3/oxygen-mcp`](../services/oxygen-mcp) | Gives Claude Code an x402 wallet (`wallet_info`, `x402_fetch`) |

## The flow

```
● curl  http://node/x402/demo/markets/top          → 402 Payment Required · $0.05 USDC
● x402-fetch http://node/x402/demo/markets/top      → 200 · { markets: [...] } · paid $0.05 via x402
● oxygen-mcp wallet_info                             → balance: $49.95 USDC
```

Run it: `pnpm --filter @web3/node demo:x402`

1. **402.** An unpaid request to a priced resource returns HTTP 402 with a spec-shaped body:

   ```json
   {
     "x402Version": 1,
     "accepts": [{
       "scheme": "exact",
       "network": "base-sepolia",
       "maxAmountRequired": "50000",
       "resource": "http://node/x402/demo/markets/top",
       "payTo": "0x…",
       "asset": "0x036CbD53842c5426634e7929541eC2318f3dCF7e",
       "maxTimeoutSeconds": 60,
       "extra": { "name": "USDC", "version": "2" }
     }]
   }
   ```

2. **Sign.** The client builds an [EIP-3009](https://eips.ethereum.org/EIPS/eip-3009)
   `transferWithAuthorization`, signs it (EIP-712, secp256k1), and base64-encodes it into an
   `X-PAYMENT` header. No transaction is broadcast by the client; the authorization is a promise a
   facilitator redeems.

3. **Verify + settle.** The resource server hands the payment to a **facilitator**. The facilitator
   recovers the signer from the signature — a tampered amount or recipient no longer recovers to the
   payer, so **the facilitator can't redirect funds**. That property is exactly why a facilitator can
   be *permissionless*: anyone can run one. On success the server returns `200` plus an
   `X-PAYMENT-RESPONSE` receipt.

## Every priced agent is automatically an x402 API

Any agent registered with a `pricing.perTask` becomes a **pay-per-call x402 service with no extra
setup** — the node auto-generates a paywalled endpoint per skill:

| Endpoint | What it is |
|----------|------------|
| `GET /x402/directory` | The catalogue of purchasable agent skills (price, payTo, endpoint). |
| `GET\|POST /x402/call/:web3Id/:skillId` | The paywall: 402 unpaid → pay → the agent runs the skill. |

**Auto-bind (#2):** the receiving wallet is the agent's **ERC-8004 address, derived deterministically
from its DID** — identical to the one the erc8004 module minted. So payments settle to the agent *and*
auto-credit its economic reputation, with no manual bind step.

**Auto-price (#1):** the per-task price (aETH minor, 2dp) is scaled to USDC atomic (6dp) — e.g.
`perTask: 500` → `$5.00` → `5000000`. Skills with no price aren't listed.

**Delivery:** on payment the node dispatches the skill as a task over the A2A connection hub. If the
agent is hosted/connected it answers synchronously and the result comes back in the HTTP response; if
it's offline the task queues (and delivers on the A2A channel) — the payment is final either way.

```
GET /x402/call/alice@web3.0/summarise?q=…      → 402 Payment Required · $5.00 USDC
   (retry with X-PAYMENT)                       → 200 · { paid:{…}, delivery:"completed", output:{…} }
```

## The node is both a resource server and a facilitator

| Endpoint | What it is |
|----------|------------|
| `GET /x402/demo/markets/top` | A real priced resource — 402 unpaid, data once paid. |
| `GET /x402/supported` | The scheme/network pairs this facilitator settles. |
| `POST /x402/verify` | Verify a signed payment (recovers the payer). |
| `POST /x402/settle` | Verify **and** settle. Point any x402 server here to accept USDC — like OpenX402. |
| `GET /x402/receipts` | Recent settlements, for the operator console. |

## Settlement is pluggable — ledger today, Base tomorrow

Set with `WEB3_X402_SETTLE`:

- **`ledger`** (default) — the payment is verified cryptographically and recorded on the node's
  **ML-DSA-signed (post-quantum) ledger** and event feed, with a deterministic tx reference derived
  from the authorization. Fully self-contained; no chain, no keys.
- **`upstream`** — verify/settle are forwarded to a real facilitator
  (`WEB3_X402_FACILITATOR_URL`, e.g. OpenX402 on Base) for live on-chain USDC settlement.

The node **never holds a private key by default** — the same safe-by-default stance as the
`SettlementProvider` rails. An operator supplies a funded key to broadcast for real.

> **The post-quantum angle.** The x402 payment envelope is classical secp256k1 — that's the price of
> interoperating with the EVM world. But the *ledger that records the settlement* is the same
> ML-DSA-signed ledger as the rest of Web3.0, so the audit trail stays quantum-resistant even where
> the rail isn't. The wider Web 4.0 stack is trust-minimized but control-light and classically
> signed; Web3.0's answer is post-quantum and control-heavy (guardrails, spend caps, authority
> seating).

## Configuration

| Env var | Meaning | Default |
|---------|---------|---------|
| `WEB3_X402_ENABLED` | Mount the x402 module. | `true` |
| `WEB3_X402_NETWORK` | Network label advertised in 402s. | `base-sepolia` |
| `WEB3_X402_ASSET` | ERC-20 (USDC) address to price in. | Base Sepolia USDC |
| `WEB3_X402_PAYTO` | Address that receives payment for the node's resources. | (placeholder; set yours) |
| `WEB3_X402_KEY` | Operator key — `payTo` is derived from it if `WEB3_X402_PAYTO` is unset. | unset |
| `WEB3_X402_DEMO_PRICE` | Price of the demo resource, atomic USDC. | `50000` ($0.05) |
| `WEB3_X402_SETTLE` | `ledger` or `upstream`. | `ledger` |
| `WEB3_X402_FACILITATOR_URL` | Upstream facilitator base URL (OpenX402 / CDP). | unset |
| `WEB3_X402_EXPLORER` | Block-explorer base for receipt links. | unset |
