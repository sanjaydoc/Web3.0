# ERC-8004 — identity, reputation & validation for Web3.0 agents

Web3.0 speaks [**ERC-8004 "Trustless Agents"**](https://eips.ethereum.org/EIPS/eip-8004) — the
Ethereum standard that gives autonomous agents a verifiable identity, a portable reputation, and
independent validation, extending Google's A2A Agent Card. Every Web3.0 agent automatically becomes
an ERC-8004 agent, so the wider ecosystem of agents and indexers built on the standard can **discover
and trust** them.

Implemented across:

| Piece | Package | Role |
|-------|---------|------|
| The three registries | [`@web3/erc8004`](../packages/web3-erc8004) | Identity / Reputation / Validation logic |
| Node module | [`services/web3-node` → `erc8004`](../services/web3-node/src/modules/erc8004.ts) | Auto-mint identities + HTTP discovery/reputation/validation |

## Three registries

- **Identity** — each agent is a transferable token (`agentId`) resolving to a registration file
  (the Agent Card). This is the anchor; the other two ask it "does this agent exist, and is the
  caller allowed to act for it?" before any write.
- **Reputation** — clients publish bounded feedback (score 0–100) with tags; anyone reads the
  aggregate. Only the agent's owner may respond; only the original client may revoke.
- **Validation** — a requester asks a named validator to verify some work (a `dataHash`); the
  validator posts a 0–100 result. Only the named validator may respond.

## Every Web3.0 agent gets an identity — automatically

When an agent joins (`POST /agents`), the node mints its ERC-8004 identity and backfills existing
agents at boot. No extra step: a Web3.0 DID becomes an ERC-8004 `agentId` with a derived, stable
`agentAddress`.

## Endpoints

| Endpoint | Purpose |
|----------|---------|
| `GET /.well-known/erc8004.json` | Discovery root: standard, registry CAIP-10, agent count. |
| `GET /erc8004/agents` | List all agent identities. |
| `GET /erc8004/agents/:agentId` | An identity + its registration file. |
| `GET /erc8004/agents/:agentId/card` | The ERC-8004 registration file (A2A card + registrations + trust models). |
| `GET /erc8004/resolve?address=…&domain=…` | Resolve an identity by address or domain. |
| `POST /erc8004/agents/:agentId/bind` | Bind a real EVM wallet (e.g. its x402 `payTo`). |
| `POST /erc8004/agents/:agentId/feedback` | Publish bounded feedback about an agent. |
| `GET /erc8004/agents/:agentId/reputation` | Aggregate score + feedback list. |
| `POST /erc8004/agents/:agentId/feedback/:i/respond` | Owner responds to feedback. |
| `POST /erc8004/agents/:agentId/feedback/:i/revoke` | Client revokes their feedback. |
| `POST /erc8004/validation/request` · `/response` | Request / return a validation. |
| `GET /erc8004/validation/:dataHash` | A validation record. |

## The registration file

Fetching `/erc8004/agents/:agentId/card` returns an A2A Agent Card extended with ERC-8004 fields:

```json
{
  "name": "Alice", "description": "A helpful agent", "version": "0.1.0",
  "skills": [ … ],
  "registrations": [
    { "agentId": 1, "agentRegistry": "web3:web3.0:node:…", "agentAddress": "0x…" }
  ],
  "trustModels": ["feedback", "inference-validation", "tee-attestation"],
  "web3": { "web3Id": "alice@web3.0", "did": "did:web3:z…", "signPublicKey": "…" }
}
```

## Ledger today, Base tomorrow

By default identities live on the node (ledger-backed), and the registry is identified by a
`web3:…` CAIP-10. Point `WEB3_ERC8004_REGISTRY` at a deployed on-chain IdentityRegistry
(`eip155:84532:0x…`) to anchor to real Base contracts — the registration files then reference the
on-chain registry, and the resolution semantics are unchanged.

> **The post-quantum angle.** ERC-8004's identity is a classical EVM address; Web3.0 derives that
> address from an **ML-DSA** key and keeps the DID + public key in the registration file. Discovery
> and reputation interoperate with the standard, while the underlying identity stays
> quantum-resistant — the same "interoperate on the wire, post-quantum underneath" stance as
> [x402](./X402.md).
